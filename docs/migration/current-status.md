# Миграция на самостоятельный Arch Linux: текущее состояние

Проверено 2026-11-03. Этот документ дополняет исторический аудит от 10 октября,
а не переписывает его результаты. Цель и границы сохраняются в
[дорожной карте](../superpowers/specs/2026-10-10-independent-tab-stack-roadmap.md).

Пользователь выбрал продолжение без прерывания работы. Logout, reload,
блокировка, suspend, установка и удаление пакетов в этой проверке не выполнялись.
Пользователь согласовал отдельную службу tab-stack и разрешил реализацию.
[Проект решения](../superpowers/specs/2026-11-03-independent-sleep-lock-design.md)
реализован в отдельной ветке `feature/independent-sleep-lock`. Инструкция:
`dotfiles/docs/sleep-lock.md` в этой ветке. На host служба не устанавливалась.

| Часть | Доказательство | Результат и граница |
| --- | --- | --- |

| Lifecycle | Живой `systemctl --user show` | Собственный target и все пять служб active; Elephant и порталы running |
| Legacy targets | Живой current-session snapshot | `graphical-session.target` и `graphical-session-pre.target` inactive |

| Polkit | Отдельная проверка метаданных | Один кандидат текущего UID, родитель ShojiWM; чтение exe запрещено EACCES. Нулевой счётчик общего snapshot не доказывает отсутствие агента |
| Locker | Установленный `lock/launch.py --check` | QML загружается, `ext-session-lock-v1` доступен; выбрана собственная bundled PAM-политика `shoji-lock` |
| PAM | Чтение политики и `pacman -Qo` | `system-auth` и `system-local-login` принадлежат pambase; `/etc/pam.d/shoji-lock` отсутствует, используется штатный fallback launcher |

Протоколы с идентификаторами процессов, путями резервных копий и подробностями
машины остаются локальными. Предыдущее подтверждение парольной разблокировки
не заменяет приёмку изменённой политики PAM: в этот раз аутентификация не запускалась.

## Что ещё отделить

1. **Системный сон.** `IdleSleep.qml` сначала вызывает locker и только после
   успешного завершения launcher выполняет `systemctl suspend`. Это покрывает
   собственный автосон панели, но не является обработчиком внешнего запроса сна.
   При начальном осмотре source не содержал потребителя `PrepareForSleep`.
   В ветке реализации теперь есть отдельный монитор logind, собственный inhibitor,
   opt-in установщик и guarded rollback. На работающем host этот разрыв пока
   остаётся: установка и живая приёмка отложены до отдельного окна.
2. **Приёмка locker.** После изменения PAM ещё нужны согласованные ручные проверки
   неверного/верного пароля и оборудования. Принятый тест изоляции панели не повторять
   без новой причины.
3. **Ядро и загрузка.** Загружено `7.2.5-3-omarchy`; пакеты `linux` и `linux-lts`
   отсутствуют. Установлены `linux-omarchy` и headers, Limine и его hooks для
   mkinitcpio/Snapper. Замена ядра требует отдельного плана и проверки загрузки;
   удаление метапакета Omarchy не делает этот участок независимым.
4. **Репозиторий и пакеты.** `[omarchy]` остаётся в pacman.conf; установлены
   Omarchy, его settings/keyring и Hyprland. Перед отключением репозитория нужна
   полная карта установленных сборок и замен. Транзакция удаления не подготовлена
   и не разрешена этим отчётом.
5. **Чистый Arch и обновление.** Нужны отдельная установка и повторное обновление
   без унаследованной конфигурации Omarchy. Текущий рабочий host этого не доказывает.

Загрузчик, шифрование, настройки других пользователей, autologin и сохранённые
профили не изменялись. Существующие пользовательские изменения в checkout
не включались в миграцию автоматически.

## Проверки исходников до реализации

- Session suite: 60 тестов, 59 прошли в sandbox, один Unix socket test пропущен
  из-за запрета bind. Затем `test_session_state.py` выполнен вне sandbox:
  все 6 тестов прошли, включая настоящий Unix peer test. Это изолированные тесты,
  не проверка нового входа или сна.
- Launcher locker: все 8 regression tests прошли; без блокировки и аутентификации.
- Общий current-session snapshot вернул REVIEW из-за недоступности exe polkit;
  его результат целиком не считается PASS. Основной session check прошёл отдельно.

Следующий обзор должен начинаться с этого документа и текущего source,
а не с повторного исполнения исторического плана установки 1Б.

## Реализация службы сна: source готов, deployment pending

- Полная discovery suite в ветке реализации: 98 тестов прошли без пропусков,
  включая Unix peer и настоящий FD/сигналы fixture logind на приватной D-Bus-шине.
- Launcher locker: 12 тестов прошли, включая общий deadline, contention и отказ
  на malformed status. QML lint и offline unit verification прошли.
- Read-only preflight нового source прошёл на текущей сессии: независимый lease,
  Python dependencies, PAM support files и бюджет logind 15 секунд. Без inhibitor,
  QML, блокировки и сна.
- Безопасная native scope проба: launcher завершился с кодом 0, пока его
  отделённый тестовый дочерний процесс оставался жив. Locker в пробе не запускался.
- Независимое code review не нашло Critical/Important проблем.

Следующий шаг: точечный план применения к свежему installed baseline, затем
отдельное согласованное окно TTY/install/relogin и ручная password/suspend приёмка.
Не устанавливать новый target drop-in в текущую пятисервисную сессию.
