# tab-stack — рабочая среда Alt Tabek

Я — **Tabek**, frontend-разработчик. Настраиваю инструменты под то, как работаю: пишу код, использую AI-агентов и автоматизирую повторяющиеся задачи. В **tab-stack** собираю свой Linux-десктоп, конфигурацию ассистентов, скиллы и скрипты.

Для меня рабочая среда — часть разработки. Если в инструменте не хватает нужного действия, я разбираюсь, как его добавить, и сохраняю результат здесь. Сначала — работающая функция, затем удобство и детали интерфейса.

Проект вырос из [howdeploy/kisa-stack](https://github.com/howdeploy/kisa-stack) и развивается под мой рабочий процесс в [tab11pm/tab-stack](https://github.com/tab11pm/tab-stack). **Alt Tabek** — мой личный бренд; **tab-stack** — проект рабочей среды. Происхождение компонентов и авторские уведомления сохранены.

## Как развивается мой десктоп

В tab-stack уже доступны:

- **Блокировка и сессия:** свой интерфейс блокировки с общим вводом на нескольких экранах, штатный выход и отдельно устанавливаемая сессия tab-stack.
- **Мониторы:** расположение, основной экран, яркость, частота и масштаб с подтверждением и автоматическим откатом.
- **Работа с окнами:** переключатель Alt+Tab и восстановление геометрии при изменении расположения мониторов.
- **Виджеты:** редактор раскладок, пресеты, выбор обоев, музыкальные кнопки и перемотка, батарея и профили питания.
- **Управление режимами:** ночной фильтр с расписанием, опциональный автосон и локальная статистика времени за ПК.
- **AI-инструменты:** опциональные виджеты лимитов, сессий, DeepSeek API и Hermes; скилл подготовки изменений к публикации.

Подробности — в [документации десктопа](dotfiles/README.md) и [обновлении от 12 октября](dotfiles/docs/update-2026-10-12.md). Код объединяет унаследованные компоненты и изменения, которые я развиваю для своего сетапа; сведения о сторонних авторах находятся в [уведомлениях](dotfiles/NOTICE.md).

## С чего начать

```bash
git clone https://github.com/tab11pm/tab-stack.git
cd tab-stack
```

**Рабочий стол:** следуйте [инструкции установки](dotfiles/docs/install.md). Она описывает зависимости, сборку закреплённых версий и предварительный просмотр установки. Отдельная сессия и настройка экрана входа устанавливаются отдельными шагами.

**Один скилл:** выберите задачу и нужную среду:

```bash
./install.sh shojiwm --codex
./install.sh researcher --claude
./install.sh voice-summary --hermes
```

Без флагов `install.sh` устанавливает выбранный скилл в Claude Code и Codex. `--hermes` включается явно. `./install.sh all` устанавливает весь каталог; существующие папки скиллов сохраняются в резервных копиях.

**Правила агентов и хуки:** настройте шаблоны по [отдельной инструкции](global-config/README.md). Установка скиллов сама по себе их не подключает.

## Работа с агентами

Я использую агентов в процессе разработки: уточнение задачи, реализация, проверка результата и разбор ошибок. Контекст проекта и повторяемые действия сохраняю в правилах и скиллах, чтобы следующий запуск опирался на уже принятые решения.

В репозитории есть шаблоны для Claude Code и Codex, а установщик скиллов поддерживает также Hermes. Требования к инструментам и особенностям среды указаны в конкретном скилле. Каталог сторонних решений не означает, что все они установлены или нужны для работы tab-stack.

## Текущий статус

Это развивающаяся рабочая среда с исходниками и инструментами установки. Я настраиваю её под свой десктоп и публикую изменения, которые можно перенести без личных данных.

Проверки исходников и установки во временный домашний каталог описаны в [журнале проверок](dotfiles/docs/validation.md). Они не подтверждают работу на любом GPU, дистрибутиве или чистой машине. Нативная обработка отпускания Alt, графическое поведение и часть сценариев запуска сессии ещё требуют проверки.

Интеграции с аккаунтами и автоматический сон по умолчанию выключены. Личные обои, настройки подключений, ключи и история активности остаются за пределами публичного репозитория.

## Куда дальше
